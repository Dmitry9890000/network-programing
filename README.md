## Описание

Программа представляет собой сетевую игру «Камень, ножницы, бумага», работающую по протоколу TCP. Сервер принимает от клиента выбранный ход, самостоятельно выбирает свой ход и определяет результат раунда: победу, поражение или ничью. Если игрок три раза подряд выбирает один и тот же вариант, сервер учитывает это и выбирает ход, который побеждает его предыдущий выбор. Клиент взаимодействует с сервером с помощью ввода команд 1, 2 или 3.

## Как собрать и запустить

Сборка проекта выполнялась с помощью компилятора **g++ (MinGW)**.

Для сборки сервера используется команда:

```bash
g++ server.cpp -o server.exe -lws2_32
```

Для сборки клиента используется команда:

```bash
g++ client.cpp -o client.exe -lws2_32
```

Чтобы запустить программу, необходимо:

1. Запустить `server.exe` в одном окне консоли.
2. Запустить `client.exe` во втором окне.
3. После подключения сервер отправит приветственное сообщение.
4. В клиенте вводить команды для игры.

Сначала необходимо запустить сервер, так как клиент подключается к нему.

## Протокол

Сервер слушает порт **9000**. Каждая команда передаётся одной строкой, после чего сервер отправляет одну строку ответа. После подключения сервер присылает приветственное сообщение с правилами игры.

| Команда | Что делает | Пример ответа |
|---|---|---|
| `1` | Выбрать камень | `You chose: Rock. Server chose: Scissors. You win!` |
| `2` | Выбрать бумагу | `You chose: Paper. Server chose: Rock. You win!` |
| `3` | Выбрать ножницы | `You chose: Scissors. Server chose: Paper. You win!` |
| `HELP` | Показать список доступных команд | В текущей версии сервера команда не реализована |
| `QUIT` | Завершить игру и отключиться от сервера | `BYE` |

## Ошибки

Если пользователь вводит неправильную команду, сервер отправляет сообщение:

`ERROR: Enter 1, 2, or 3.`

Например, если вместо цифр 1, 2 или 3 ввести другую команду, сервер сообщит об ошибке и продолжит ожидать правильный ввод.

Если клиент отключается, сервер закрывает соединение и возвращается в режим ожидания следующего подключения.

## Что я изменил в шаблоне

В шаблон сервера была добавлена логика игры «Камень, ножницы, бумага».

Были добавлены:

- Переменные `rockCount`, `paperCount` и `scissorsCount` для подсчёта количества выборов каждого хода игроком.
- Функция `moveName()`, которая преобразует числовое значение хода в его название.
- Функция `onConnect()`, которая сбрасывает счётчики при подключении нового клиента и отправляет приветственное сообщение с правилами игры.

- Генерация случайного хода сервера с помощью `rand()`.
- Дополнительная логика, которая позволяет серверу учитывать повторение одного и того же хода игроком три раза подряд и выбирать против него выигрышный вариант.

Самым сложным было реализовать правильное определение победителя и дополнительную логику выбора хода сервера при повторении игроком одного и того же варианта.

Также были сохранены основные сетевые функции шаблона: создание сокета, привязка к порту, ожидание подключения клиента и обмен сообщениями по TCP.

## Ответы на контрольные вопросы

**1. В каком порядке сервер вызывает socket, bind, listen, accept и что делает каждый вызов?**

Сервер вызывает функции в следующем порядке:

1. `socket()` — создаёт сокет, через который будет происходить обмен данными.
2. `bind()` — привязывает сокет к IP-адресу и порту 9000.
3. `listen()` — переводит сокет в режим ожидания подключений клиентов.
4. `accept()` — ожидает подключения клиента и принимает его. После подключения создаётся отдельный сокет для общения с этим клиентом.

После этого сервер может принимать команды от клиента и отправлять ответы.

**2. Почему клиенту не нужны bind и listen? Какой порт получает клиент?**

Клиенту не нужно ожидать подключения других устройств, поэтому ему не требуются функции `bind()` и `listen()`.

Клиент самостоятельно подключается к серверу с помощью функции `connect()`. Операционная система автоматически назначает ему свободный временный порт, который используется для соединения с сервером.

**3. Зачем нужен htons(PORT)?**

Функция `htons()` преобразует номер порта из порядка байтов компьютера в сетевой порядок байтов (Network Byte Order).

Это необходимо для правильной передачи номера порта между устройствами по сети. В моей программе функция используется при настройке адреса сервера:

```cpp
addr.sin_port = htons(PORT);
```

**4. Почему recvLine читает до символа \n, а не просто вызывает recv один раз?**

TCP передаёт данные в виде непрерывного потока байтов и не сохраняет границы отдельных сообщений.

Поэтому один вызов `recv()` может получить только часть сообщения или сразу несколько сообщений.

Функция `recvLine()` читает данные по одному байту до появления символа `\n`. Это позволяет получить полную строку команды от клиента. Символ `\r` при этом пропускается.

**5. Опишите протокол своего варианта: какие команды, какие ответы, что сервер делает при ошибке?**

В моей программе реализована сетевая игра «Камень, ножницы, бумага». Клиент отправляет серверу одну из трёх команд:

- `1` — камень (Rock).
- `2` — бумага (Paper).
- `3` — ножницы (Scissors).
- `QUIT` — завершение соединения.

После получения команды сервер проверяет её правильность, выбирает собственный ход и сравнивает его с ходом игрока.

Если игрок и сервер выбрали одинаковый вариант, сервер отправляет сообщение `It's a draw!`.

Если игрок выбрал выигрышную комбинацию, сервер отправляет `You win!`. Если сервер оказался победителем, отправляется `You lose!`.

Также реализована дополнительная логика: если игрок три раза подряд выбирает один и тот же вариант, сервер выбирает ход, который побеждает этот вариант.

Если пользователь вводит неправильную команду, сервер отправляет сообщение:

`ERROR: Enter 1, 2, or 3.`

При получении команды `QUIT` сервер отправляет ответ `BYE` и закрывает соединение с клиентом.
